# Contextual feedback in Muse

Verified on the Muse Mac client on 27 September 2026, in a separate private
**Office Feedback Test**. The personal Office was excluded. This tests an
Office generated by Muse from the instructions, alongside the reference app.

## Observed result

1. Submitted one synthetic task comment through the artifact with Markdown,
   a screenshot and a 7.8-second spoken WAV. Enter kept a newline;
   Shift+Enter submitted it. Both files remained attached to that comment.
2. Played the entire saved audio in the actual Mac client.
3. A natural scheduled run picked up the typed update, recorded an owned next
   action and replied on the same task. Later runs continued after it was read.
4. The owner retrieved the private bytes, inspected the screenshot (Otto's
   mobile team card), and accurately transcribed the WAV using a private local
   Whisper tool. The requested title was present only in the spoken file.
5. After the action repair below, a natural run changed the note's **actual
   title** to `feedback received` and added “Screenshot and voice feedback
   reached the same task owner.” to its content. Existing content and comments
   were preserved. The native note page independently showed both changes.
6. The task showed the checked result and final owner reply on the original
   comment thread, then Done. The final result record is dated 11:52 CDT.

## Failures found and corrected

- The host blocks native Web Share handoff from the artifact. A deliberate
  microphone probe also returned `NotAllowedError`. API presence was not proof
  of support. Audio-file attachment works; in-artifact recording is not claimed
  to work on this Mac host. Native Muse chat remains the primary input.
- The generated audio player initially failed. Its repair uses a properly typed
  local media source; the reference app serves private audio with byte ranges.
- The agent initially received only filenames. Bounded private attachment
  retrieval was added and verified; files are never published for agent access.
- The worker lacked transcription. A private local tool was prepared in an
  isolated environment, with no paid API or external upload. Future setup must
  verify actual audio understanding before promising voice follow-up.
- Earlier runs falsely closed blocked work. They were reopened with history
  preserved. The hat now requires blocked work to stay open and the requested
  record to be read back before completion.
- The generated artifact omitted the reference `upsert_note` action. An earlier
  run wrote the intended title in a comment instead of renaming the note. That
  was rejected as incomplete. The action was repaired and verified with a no-op;
  a later natural run performed the actual change.

## Schedule and cleanup

Muse reported the successful natural occurrence at 11:50:24 CDT, with the
verified result and final reply at 11:52:26 CDT. The final reply is 38 on the
original comment-30 thread. It reported persisted checkpoints, scheduler
